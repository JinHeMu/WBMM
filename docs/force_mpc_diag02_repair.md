# Force-MPC diag02 修复与验证

2026-10-09。基于最长的 diag02 实机包和对应任务快照实施；本轮验证没有连接实机。

## 修复内容

1. **连续航向角。** MRT 在读取合法 odometry 后，在状态锁内累计相邻 yaw 的最短角差。第一次保留原始 yaw；跨越 ±π 和多圈运动时向 MPC 提供连续坐标。修复 warm-start 线性控制器把约 2π 的表示跳变当作状态误差的问题。
2. **关节状态与 TF 发布链。** 实机采用 `ros2_control_node → joint_state_broadcaster → /joint_states → robot_state_publisher → /tf`。规范配置的 `controller_manager.update_rate` 已是 125 Hz，JSB 随控制循环发布，FTS broadcaster 也在这条循环内。当前执行控制器是 `ForwardCommandController`；未启用的轨迹控制器的 `state_publish_rate` 不控制 JSB 或 TF。
   实机 force_mpc 入口现在将 RSP 的 `publish_frequency` 上限设为 **250 Hz**，使 125 Hz 关节样本充分通过。这个上限不会产生额外的关节采样。通用硬件入口新增 `robot_state_publish_frequency` 参数，默认仍为 20 Hz。测试证实，若上限恰好设为 125 Hz，8 ms 时间戳抖动会导致大量隔帧发布，因此最终采用两倍余量。
3. **力滤波采样间隔。** 要求带时间戳的输入使用连续进入处理器的原始样本时间戳之差，包括 tare 样本；等待 TF 后的集中投递不再改变 LPF 的等效响应。首次样本使用初始化间隔，reset 清空时序状态；兼容入口保留 steady-clock 间隔。已有时间戳递增和新鲜度检查先于处理执行。
4. **实机规划参数。** 六轴规划速度上下界从 ±0.5 改为 **±0.2 rad/s**，与当前执行速度上限对齐。启用奇异值过程和终端代价，`minSingularRef=0.10`，对照测试后选用 `minSingularWeight=0.50`，终端 `weightScale=1.0`。仍只评价六轴 arm 的 pose Jacobian，角速度行按 0.30 m 缩放。
5. **仿真兼容。** 当前 MuJoCo 3.12 与 NumPy 1.21 的枚举比较会使 tuple 成员检查误拒绝合法关节类型。仿真伺服验证对关节类型显式转换为 Python int，原有传动和增益检查保持有效。

保持按原始 wrench 时间戳查询 TF、50 ms 等待、故障锁存、重力补偿、质量/阻尼/死区、0.10 m 和 0.35 rad 跟踪保护。没有新增 latest-TF 回退、奇异值硬停或自动复位。用户预先修改的 README 和公共质量/阻尼配置予以保留。

## 离线求解对照

从长包取录制相对时间 72–75.48 s 的 observation，每两个样本取一个，共 218 行；各行配对截至该接收时刻最近的 EE target。重建 warm-start 求解，三组共享输入、目标和优化后求解器，分别使用原任务/原 yaw、原任务/连续 yaw、最终任务/连续 yaw。

| 跨界之后的首个规划输入峰值 | 原任务 / 原 yaw | 原任务 / 连续 yaw | 最终任务 / 连续 yaw |
|---|---:|---:|---:|
| 最大关节速度绝对值 rad/s | 6.8355 | 0.4980 | 0.1950 |
| 底盘线速度绝对值 m/s | 0.9207 | 0.0980 | 0.0924 |
| 底盘角速度绝对值 rad/s | 0.6909 | 0.3981 | 0.3954 |

这验证了 yaw 表示跳变触发 warm-start 异常的机制。离线运行没有恢复原进程在包开始前的求解器状态，也没有闭环执行新策略，不能据此推断修复后的实机轨迹。规划上下界仍通过现有软约束实现，执行层速度限制继续独立生效。

## TF 时序对照

独立 ROS 域，仅启动 RSP 和力传感器处理器，使用真实 URDF/标定配置、带时间戳的合成关节和力数据；不启动硬件驱动。每组 125 Hz 输入持续 10 s。

| RSP 上限 | TF 样本数 | TF 间隔 P50 / P95 ms | 处理后力样本数 | 处理后力年龄 P50 / P95 ms |
|---|---:|---:|---:|---:|
| 20 Hz | 179 | 56.000 / 56.063 | 1067 | 20.522 / 51.135 |
| 125 Hz | 646 | 15.999 / 16.097 | 1249 | 10.524 / 10.880 |
| **250 Hz** | **1249** | **8.000 / 8.033** | **1248** | **3.190 / 10.880** |

每组发送 1250 个样本，结束时未排空队列，末尾计数差不能直接视为数据丢失。三组均未出现运行期 WRENCH_TF；20 Hz 组复现了长包中的约 56 ms TF 间隔和约 51 ms 力数据年龄。该对照说明时序余量改善，不代表已复现或证明消除用户另一次启动/退出时的 TF 报错。

## 奇异值权重对照

独立、无界面的 MuJoCo force_mpc 启动，使用实机任务参数和当前公共导纳参数；合成输入送入 virtual wrench command，经原虚拟传感器和力控制链路执行。相同仿真时钟序列：零力 3 s，TCP -Z 方向 5 N 持续 8 s，释放 4 s，反向 5 N 持续 6 s，释放 4 s。各组重新启动。

| minSingularWeight | 实测最小奇异值 | TCP 误差 RMS mm | 最大 TCP 误差 mm | 故障 / 意外碰撞 |
|---|---:|---:|---:|---|
| 0.10 | 0.02712 | 33.54 | 61.95 | 无 |
| 0.20 | 0.03569 | 33.47 | 62.41 | 无 |
| **0.50** | **0.05105** | **33.16** | **62.34** | **无** |

选择 0.50 是因为本组输入下裕度较大、跟踪误差相近。阈值 0.10 是软代价参考，不保证实际最小奇异值始终高于 0.10，也不能保证所有牵引方向都避开肘部伸直。

另保留 0.10 权重、10 N 持续输入的失败记录：TCP 位置误差达到约 100.06 mm，触发 `FAULT_TRACKING_ERROR`，当时最小奇异值为 0.09240。更大的持续牵引仍可能使目标超出当前速度或构型下的跟踪能力；本次没有放宽保护或据此改动导纳参数。求解耗时受同时运行的离线求解和主机负载影响，不将这些组的耗时差解释为权重带来的性能收益。
