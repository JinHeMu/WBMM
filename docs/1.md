你这个问题本质上是要把“建图”和“之后重新定位”分成两套坐标系来处理：

- **2D 地图**：长期全局地图，使用 `map` 坐标系。
- **3D ESDF**：也应该是长期全局地图，最好直接建立在 `map` 坐标系下。
- **odom**：每次开机后从零开始的局部连续坐标系，只用于里程计/控制。
- 每次开机后通过 2D 定位得到 `map -> odom`，这样就能把“机器人在 map 中的位置”和“3D ESDF 在 map 中的位置”统一起来。

当前仓库的问题在于：

- `real_slam.launch.py` 里 slam_toolbox 是 `mode: mapping`，没有加载已有地图做 localization。
- `d455_bag_esdf.launch.py` 离线建 ESDF 时，`global_frame` 和导出 `frame_id` 都写死为 `odom`。
- `remani_mpc_tracking.launch.py` 里 REMANI 的 `grid_map.frame_id` 和 `fsm.planning_frame` 也是 `odom`。
- REMANI→OCS2 bridge 目前只支持固定的 `planner_to_ocs2_x/y/yaw`，不支持动态 `map -> odom` TF。

所以要实现你说的“一启动就知道自己在已建好的 2D 地图和 3D ESDF 中的位置”，需要做以下几步。

---

## 1. 推荐的整体架构

```text
保存的 2D 地图 (map frame)
保存的 3D ESDF (map frame)
          │
          ▼
map_server + AMCL / slam_toolbox localization
          │
          ▼
发布 map -> odom
          │
          ▼
REMANI 在 map frame 中规划
          │
          ▼
REMANI→OCS2 bridge 把 map 轨迹转换到 odom
          │
          ▼
OCS2 MPC/MRT 继续在 odom 中控制机器人
```

这样：

- 2D 定位负责回答“我在 map 哪里”。
- 3D ESDF 也保存在 map 下，所以 REMANI 可以直接查询。
- OCS2/MRT 不需要大改，仍然使用 odom 做连续控制。

---

## 2. 建图阶段需要保存什么

你之前已经用 rosbag 离线建图，建议从同一份 bag 中同时得到：

```text
lab_map.pgm / lab_map.yaml        # 2D 占据栅格地图，map 坐标系
lab_map.posegraph / lab_map.data  # 如果要用 slam_toolbox localization，需要序列化地图
d455_bag_remani_esdf.npz          # 3D ESDF，建议导出为 map 坐标系
```

2D 地图可以通过当前 `d455_bag_esdf.launch.py` 里的 `map_snapshot_saver` 保存，也可以用：

```bash
ros2 run nav2_map_server map_saver_cli -f ~/WBMM/maps/lab_map
```

如果后续要用 slam_toolbox 的 localization 模式，最好在建图现场保存序列化地图：

```bash
ros2 service call /slam_toolbox/serialize_map \
  slam_toolbox/srv/SerializePoseGraph \
  "{filename: '/home/你的用户名/WBMM/maps/lab_map'}"
```

## 3. 把 3D ESDF 导出到 map 坐标系

当前 `d455_bag_esdf.launch.py` 里有一句：

```python
"global_frame": "odom",
```

并且 exporter 参数也是：

```python
'frame_id': 'odom',
```

需要改成可配置，默认使用 `map`：

```python
DeclareLaunchArgument('global_frame', default_value='map')

# nvblox 使用 map 作为全局坐标系
"global_frame": LaunchConfiguration('global_frame'),

# ESDF 导出也使用 map
'frame_id': LaunchConfiguration('global_frame'),
```

这样离线回放 bag 时，nvblox 会直接利用 bag 里的 `map -> odom -> base_footprint -> d455` TF，把 3D ESDF 建立在 `map` 坐标系下。

之后 REMANI 加载的 `d455_bag_remani_esdf.npz` 就是 map 坐标系，和 2D 地图天然对齐，不需要再额外维护“2D 和 3D 地图的偏移关系”。

---

## 4. 后续开机定位：两种方案

### 方案 A：使用 AMCL + map_server（推荐，较简单）

启动时：

1. 启动底盘、IMU、LiDAR、EKF，得到 `/odometry/filtered` 和 `odom -> base_footprint`。
2. 启动 `map_server` 加载保存的 `lab_map.yaml`，发布 `/map`。
3. 启动 AMCL，订阅 `/scan` 和 `/odometry/filtered`，发布 `map -> odom`。
4. 关闭 slam_toolbox 的 mapping 节点，保证 `map -> odom` 只有一个发布者。

AMCL 需要给一个初始位姿估计：

- 如果机器人每次都从固定的充电桩/起点启动，可以把该位姿写进参数。
- 如果随机位置启动，可以在 RViz 中用 `2D Pose Estimate` 点一下大概位置。
- 完全任意位置、无人干预的全局定位需要额外做全局重定位，或者使用更专用的激光全局定位包。

### 方案 B：使用 slam_toolbox localization 模式

在 `slam_toolbox_real.yaml` 基础上新增一个 localization 配置：

```yaml
slam_toolbox:
  ros__parameters:
    mode: localization
    map_file_name: /home/你的用户名/WBMM/maps/lab_map
    map_start_pose: [0.0, 0.0, 0.0]
    map_start_angle: 0.0

    odom_frame: odom
    map_frame: map
    base_frame: base_footprint
    scan_topic: /scan

    resolution: 0.05
    max_laser_range: 30.0
    minimum_time_interval: 0.05
    transform_publish_period: 0.02
    transform_timeout: 0.5
    tf_buffer_duration: 30.0
    throttle_scans: 1
    use_scan_matching: true
    use_scan_barycenter: true
    minimum_travel_distance: 0.08
    minimum_travel_heading: 0.08
    scan_buffer_size: 20
    scan_buffer_maximum_scan_distance: 20.0
    link_match_minimum_response_fine: 0.1
    link_scan_maximum_distance: 1.5
    loop_search_maximum_distance: 3.0
    do_loop_closing: false
    correlation_search_space_dimension: 0.5
    correlation_search_space_resolution: 0.01
    correlation_search_space_smear_deviation: 0.1
    loop_search_space_dimension: 8.0
    loop_search_space_resolution: 0.05
    loop_search_space_smear_deviation: 0.03
    distance_variance_penalty: 0.5
    angle_variance_penalty: 1.0
    fine_search_angle_offset: 0.00349
    coarse_search_angle_offset: 0.349
    coarse_angle_resolution: 0.0349
    minimum_angle_penalty: 0.9
    minimum_distance_penalty: 0.5
    use_response_expansion: true
```

同样，`map_start_pose` 是初始猜测，不是完全自动全局定位。  
如果机器人不在初始猜测附近，可能需要通过 RViz 给一个更接近的初始位姿，或者先让机器人原地转一下帮助收敛。

## 5. 让 REMANI 和 OCS2 使用 map 坐标系

这是最关键的一步。

### 短期临时做法

如果只在固定起点、短距离小范围测试，可以：

- 开机后等 AMCL/slam_toolbox 收敛。
- 读取当前 `map -> odom`。
- 把 3D ESDF 从 map 转换到当前 odom，然后继续用现在的 `remani_mpc_real.launch.py`。
- 设置 `static_esdf_offset_*` 为 map→odom 的平移。

但问题是 `map -> odom` 会随着定位修正而变化，所以这不是长期可靠方案。

### 长期正确做法

推荐让 REMANI 直接在 `map` 坐标系下规划：

1. 修改 `remani_mpc_tracking.launch.py`：
   - `grid_map.frame_id := map`
   - `fsm.planning_frame := map`
   - `grid_map.static_esdf_file` 使用 map 坐标系下的 NPZ
   - `grid_map.static_esdf_offset_* := 0`

2. 修改 `remani_to_ocs2_reference_bridge`：
   - 增加 TF 监听
   - 每次发布参考轨迹时，通过 `map -> odom` 或 `odom -> map` 动态转换
   - 替换当前固定的 `planner_to_ocs2_x/y/yaw`
   - 将 REMANI 在 map 中规划的 `[x, y, yaw, q1..q6]` 转换到 OCS2 的 odom 坐标系

3. 或者另一种做法：
   - 新增一个节点，把 `/odometry/filtered` 通过当前 `map -> odom` 转换成一个“map 坐标系下的 odometry”话题。
   - MRT 改订阅这个 map odometry，并把 `world_frame` 设为 `map`。
   - REMANI 也在 map 下规划。
   - 这样 bridge 就不需要动态 TF 转换，因为 OCS2/MRT 和 REMANI 都在 map 下工作。

第二种做法对现有代码改动更集中，但需要新增一个 odometry 坐标转换节点，并且要小心 `odom -> base_footprint` 和 `map -> odom` 的 TF 所有权。

## 6. 当前仓库的落地步骤建议

按顺序做：

1. **改离线 ESDF 导出为 map 坐标系**
   - `d455_bag_esdf.launch.py` 增加 `global_frame` 参数，默认 `map`。
   - exporter 的 `frame_id` 跟随 `global_frame`。

2. **保存 2D 地图**
   - 从 bag 或现场保存 `lab_map.pgm/yaml`。
   - 如果使用 slam_toolbox localization，再保存 `lab_map.posegraph/data`。

3. **新增 localization 启动**
   - 在 `tracer_jaka_localization` 或 `tracer_jaka_bringup` 中增加一个 `localization_real.launch.py`。
   - 启动 `map_server` + AMCL，或 slam_toolbox localization。
   - 确保只发布一个 `map -> odom`。

4. **修改 REMANI 规划坐标系**
   - 让 REMANI 使用 `map` frame。
   - 让 ESDF 加载 map 坐标系下的 NPZ。

5. **打通 map → odom 转换**
   - 修改 REMANI→OCS2 bridge 支持动态 TF，或新增 map odometry 发布节点。

6. **集成到 bringup**
   - 把 `localization_real.launch.py`、REMANI、OCS2 组合成一个新的 `remani_mpc_localized_real.launch.py`。

---

## 7. 需要特别注意的点

- `map -> odom` 只能有一个发布者。不要同时运行 slam_toolbox mapping、slam_toolbox localization、AMCL。
- `odom -> base_footprint` 继续由 `robot_localization` 发布。
- 3D ESDF 和 2D 地图必须来自同一份 bag / 同一次建图，并且都统一到 `map` 坐标系，否则会有偏移。
- “完全任意位置自动定位”不是加载地图就能保证的。2D 激光定位通常需要一个初始位姿估计；如果要全自动，需要额外的全局定位能力，或者机器人从已知 home 点启动。
- 当前 `remani_mpc_real.launch.py` 是我们刚加的“基于 odom + 离线 ESDF”的实机入口，它还不能直接满足你这个问题。要支持持久化地图定位，需要按上面第 5 步把坐标系改成 map 并打通动态 TF。
