# 擦黑板恒力控制设计

## 结论

恒力控制**不放在 MPC 代价里**,而是放在 **MPC 参考侧的导纳(admittance)外环**中。
`wipe_planner` 已经内置了这个机制的完整雏形(`ForceAdmittance` + `forceCorrectedState`),
当前只是被配置 `force_control_enabled: false` 关闭,验证通过后打开即可。

```
FTS (WrenchStamped /jaka_fts_broadcaster/wrench)
   │
   ▼
ForceAdmittance 1 维导纳(板法线方向)          node.cpp wrenchCallback
   │  offset_dot = G·(F_filtered − F_des) − L·offset
   ▼
forceCorrectedState: 法线位移 → 关节修正(底座不动)  planner.cpp:1164
   ▼
修正后的 9 维参考 → OCS2 MPC 跟踪 → 机器人
```

## 为什么不在 MPC 代价里

1. OCS2 模型是**运动学速度输入**模型:状态 `[x, y, yaw, q1..q6]`,
   输入 `[v, ω, q̇1..q̇6]`(见 `WheelBasedMobileManipulatorDynamics.cpp`),
   **模型中没有接触力**。要把力放入代价,必须先把接触动力学(弹簧-阻尼 +
   接触刚度)写进系统方程,而黑板/板擦的实际刚度 MPC 无法知道,力预测只能是开环猜测。
2. MPC 对力的唯一"反馈"是位姿观测,接触力本身不进 observation,
   因此"力代价"实际上是一个依赖假想刚度的开环项,环境刚度错了整条最优轨迹就错了。
3. 恒力接触的标准做法是**混合位置/力控制**:法线方向力控制、切向位置控制。
   把力放进 MPC 代价等于要求优化器自己完成这个分解,复杂且脆弱;
   而 wipe_planner 已经把 tool0 +Z 固定在板法线方向,1 维导纳外环就是天然的混合控制实现。

## 为什么参考侧导纳是对的层次

对比四个候选位置:

| 位置 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| MPC 代价内 | 理论上一条龙 | 需要接触模型、刚度不可知、力开环 | 不推荐 |
| **MPC 参考侧导纳(现有设计)** | 不动 MPC 核心;MPC 继续保证关节限位/自碰撞/整机可行;底盘路径不受扰动;仿真实机同 topic 契约 | 带宽受参考发布率(20 Hz)限制 | **推荐** |
| MRT 输出层导纳 | 带宽最高(100 Hz) | 要自写雅可比反解、限位与自碰撞检查,与 MPC 职责重复;实机仿真对拍成本高 | 带宽不够时的升级选项 |
| JAKA 原生力控(实机 SDK `enable_force_control`) | 厂商闭环、带宽高 | 只控臂不控底盘;仿真(MuJoCo)无对应实现,破坏 sim-real 一致性 | 实机备选 |

关键点:导纳外环只修正**板法线方向**这一个自由度,切向擦除路径与底盘运动
完全由位置环(名义轨迹 + 虚拟进度)负责。这正是 README 中
"A normal admittance correction can maintain force without changing the base path"
的含义。

## 导纳律与稳态分析

设导纳律为

\[
\dot{d} = G\,(F_{\text{fil}} - F_{\text{des}}) - L\,d,\qquad |d| \le d_{\max}
\]

其中 \(d\) 为法线推深修正量(m),\(G\) 导纳增益(m/s/N),\(L\) leak(1/s)。
稳态(\(\dot d = 0\))时

\[
d^* = \frac{G}{L}\,(F - F_{\text{des}})
\]

接触力又满足环境刚度 \(k\):\(F \approx F_0 + k\,d^*\),联立得稳态力误差

\[
F - F_{\text{des}} \approx \frac{L/G}{k}\,(F_{\text{des}} - F_0)
\]

含义:

- **leak 的作用**:接触丢失后 offset 以时间常数 \(1/L\) 回零,防止"推空"后继续前冲。
  代价是稳态力存在与 \(1/k\) 成正比的偏差。
- 黑板刚度大(k ≳ 10⁵ N/m)时 \(d^*\) 极小,误差可忽略;
  板面软、板擦带吸盘或长杆柔性大(k 小)时误差会显现,
  需要增大 \(G\) 或减小 \(L\) 重新权衡。
- 当前默认参数:\(G=4.5\times10^{-4}\) m/s/N,\(L=1.5\) 1/s,
  \(d_{\max}=25\) mm,\(F_{\text{des}}=12\) N,硬停 35 N / 恢复 25 N。

## 与虚拟进度 τ 的耦合(重要)

`projectProgress` / `progressMetric` 用**未修正**的名义轨迹做投影与误差度量,
而发布给 MPC 的是**修正后**的参考。因此持续的导纳推深会被算成跟踪滞后,
从而拖慢 \( \dot{\tau} \)。两个缓解办法:

1. 在 `progressMetric` 中把已知 offset 的法线分量从实测末端位姿里扣除;
2. 对**修正后**的参考做投影(修正量小、慢变,投影歧义风险低)。

当前参数下 25 mm 推深对应 EE 度量约 0.31、关节度量约 0.33,
合计低于 soft 阈值 0.7,一般不会触发,但调大 \(d_{\max}\) 或增益后必须复查这个耦合。

## 落地步骤

1. `wipe_planner.yaml` 打开 `force_control_enabled: true`,其余参数保持默认。
2. 仿真里确认 `/jaka_fts_broadcaster/wrench` 有输出:
   `ros2 topic echo /jaka_fts_broadcaster/wrench`,
   接触段法线分力(Fz,已取绝对值)应稳定在期望力附近。
3. 确认传感器坐标系与安装:规划器保证接触段 tool0 +Z 指向板内,
   `force_axis: "z"` + `force_use_absolute: true` 即可忽略安装朝向符号,
   但传感器 frame 必须与 tool0 对齐。
4. 调参顺序:先 `desired_force`(planner 默认 12 N)→ 再 `force_filter_alpha`
   (传感器噪声)→ 然后 `admittance_gain` / `admittance_leak`(响应速度与稳态误差权衡)→
   最后 `admittance_max_offset`(防止软板面推穿)。
   观察话题 `/wipe_planner/normal_force` 与 `/wipe_planner/admittance_offset`。
5. 若力跟踪过慢/振荡且调参无效,才考虑升级:
   先把 `publish_rate` 20 → 50 Hz;仍不够再在 MRT 输出层加关节空间导纳修正
   (需补限位与自碰撞检查)。
6. 实机迁移:用同一 topic 名发布实机 FTS 的 WrenchStamped
   (先做重力补偿与零漂标定,`ft_compensator.hpp` 已具备 MLP 预测能力),
   仿真调好的导纳参数直接迁移。
7. 安全:35 N 硬停(参考钳位为当前状态 + MRT 零速输出)与 MRT 层兜底保持开启。
